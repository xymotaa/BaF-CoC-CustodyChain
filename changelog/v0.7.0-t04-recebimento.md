# v0.7.0 — T-04 Recebimento

_2026-09-23_

## O que foi feito

Tela de recebimento, rota `/recebimento`, `RecebimentoController`, view
`Views/Recebimento/Index.cshtml`. Lista movimentações `PENDENTE` cujo
destino é o usuário logado, uma linha por item com dois formulários
inline: confirmar (número do lacre) ou recusar (motivo).

### Confirmar recebimento

Compara o número do lacre informado contra o lacre `INTACTO` mais recente
do vestígio (Seção 10.6: "conferência do lacre"):

- **Lacre confere:** vestígio vai para `Recebido`/etapa 7, custódia
  transfere para o destino, movimentação `ACEITA`,
  `CondicoesAdequadas=true`. Emite Credencial #3 do Quadro 14
  (`RECEBIMENTO`).
- **Lacre diverge (RN21):** vestígio vai para `CustodiaComprometida`, não
  `Recebido` — a divergência é o próprio resultado registrado, não um
  erro silencioso. Emite credencial e registro no ledger com evento
  `ROMPIMENTO`, para deixar rastro explícito do que aconteceu.

Em ambos os casos `AprovadoPorId` = usuário logado (destino), que por
construção nunca é igual ao `CriadoPorId` (origem, quem criou a remessa)
— RN16 satisfeita estruturalmente, não só validada.

### Recusar recebimento

Motivo obrigatório (RN19). Movimentação vai para `RECUSADA`, vestígio
reverte para `Coletado` e a custódia volta para a origem da remessa —
"nada fica em limbo": o item volta a aparecer disponível para uma nova
remessa em T-05, como qualquer vestígio recém-coletado.

## Decisões e por quê

- **Comparação de lacre contra o registro mais recente com
  `Situacao=INTACTO`**, não contra um campo solto no formulário de
  remessa. O lacre é uma entidade própria com histórico (encadeamento via
  `LacreAnteriorId`), então a fonte de verdade do "lacre esperado" é essa
  tabela, não um valor copiado.
- **Divergência de lacre não bloqueia a operação, ela a registra.** RN21
  diz explicitamente "não pode ser revertido silenciosamente" — por isso
  o fluxo segue até salvar o estado `CustodiaComprometida` e emitir
  credencial/registro no ledger, em vez de simplesmente rejeitar o
  formulário com um erro de validação comum.
- **Formulários inline na lista**, um por item, em vez de página de
  detalhe separada — decisão já tomada com o usuário, mantém a tela
  compacta para o volume esperado de itens em trânsito.
