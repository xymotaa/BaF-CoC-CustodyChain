# v0.4.0 — Layout base, T-01 (login) e T-02 (dashboard)

_2026-09-23_

## O que foi feito

Shell visual completo da aplicação (sidebar retrátil + navbar, previsto na
T-02 do Quadro 33) e as duas primeiras telas funcionais: T-01 (login por
credencial DID) e T-02 (dashboard com dados reais do banco).

### Identidade visual

Sistema de design próprio, sem framework de terceiros (Bootstrap e jQuery
do template padrão foram removidos):

- `wwwroot/css/tokens.css` — paleta neutra slate + acento único azul
  institucional (`#2c4a6e` claro / `#6f97c4` escuro), com suporte a
  `prefers-color-scheme` e a um atributo `data-theme` para futura
  alternância manual. Off-black/off-white em vez de preto/branco puros.
- `wwwroot/fonts/` — Source Sans 3 (texto) e JetBrains Mono (hashes, DIDs,
  códigos, métricas) self-hosted em WOFF2, com `font-display: swap` e os
  arquivos de licença (SIL OFL) de cada família.
- `wwwroot/css/base.css`, `layout.css`, `componentes.css` — reset mínimo,
  grid da sidebar/navbar, componentes (botão, campo de formulário,
  alerta, cartão, selo).
- `Views/Shared/_IconesSvg.cshtml` — conjunto fechado de ~15 ícones
  outline inline (sem biblioteca externa), referenciados via `<use>`.

### T-01 — Login (`/entrar`)

`AutenticacaoController` + `Views/Autenticacao/Entrar.cshtml`, layout
minimalista sem sidebar (`_LayoutMinimo.cshtml`). Formulário: seleção de
credencial DID (populada a partir dos intervenientes `ATIVO` no banco,
mesmos 5 usuários do seed) + senha da wallet. Autenticação via cookie
(`Microsoft.AspNetCore.Authentication.Cookies`); todo o resto da
aplicação exige `[Authorize]`.

### T-02 — Dashboard (`/`)

`HomeController.Index` busca contagens reais do banco (vestígios por
estado, processos ativos, registros pendentes no ledger) e renderiza
métricas + lista de estados, com estado vazio tratado explicitamente
(nenhum número inventado).

### Navbar dinâmica

`_Layout.cshtml` lê o usuário autenticado via `ClaimsPrincipal` (nome,
perfil, iniciais calculadas) em vez de texto fixo, e inclui logout.

## Decisões e por quê

- **Duas das três skills de design instaladas (`frontend-design`,
  `design-taste-frontend`) são voltadas a landing pages/portfólios em
  React+Tailwind com animações GSAP** — a própria `design-taste-frontend`
  declara "not dashboards, not data tables, not multi-step product UI"
  no cabeçalho. Por decisão do usuário, apliquei só os princípios
  transferíveis a um dashboard institucional: tipografia deliberada (não
  Inter/genérico), paleta com um único acento consistente, WCAG AA em
  claro e escuro, dark mode desde o início, label acima do input com erro
  abaixo, cards só onde comunicam hierarquia real, sem números fake, sem
  hero/marquee/scroll-hijack (não se aplicam aqui).
- **CSS nativo com variáveis, sem framework de UI.** Bootstrap/jQuery do
  template padrão foram removidos porque geram uma identidade visual
  genérica que a marca do TCC não pede, e adicionam peso sem necessidade
  (o app não usa nenhum componente JS interativo complexo nesta fase).
- **Sidebar retrátil via `<input type="checkbox">` + CSS**, sem
  JavaScript. Funciona em qualquer navegador, é acessível via teclado
  (label associado ao checkbox) e evita introduzir uma dependência de
  bundler/JS só para isso.
- **Senha da wallet aceita qualquer valor não vazio no login**, por
  enquanto. Não há wallet real implementada ainda (ela vive no
  dispositivo do titular, fora do servidor, por design da arquitetura).
  Documentado no código do controller para não passar despercebido.
- **Navbar mostra o usuário via claims reais**, não mais hardcoded —
  elimina um placeholder que teria sido fácil esquecer de trocar depois.
- **Itens de menu além de Painel/Login ficam com `href="#"` e
  `aria-disabled`** — as telas T-03 a T-11 ainda não têm controller/view;
  isso evita links mortos silenciosos enquanto sinaliza visualmente o que
  falta construir.

## Validado

- `dotnet build` limpo, 0 erros/avisos
- Servidor rodando localmente: `/entrar` retorna 200 com os 5 usuários de
  teste no seletor (acentuação correta), fluxo de login completo via
  `curl` com cookie + antiforgery token confirmado (redirect 302 → `/`
  com cookie de sessão), rota protegida sem login redireciona para
  `/entrar?ReturnUrl=%2F`
- Dashboard renderiza métricas reais do banco (0 em tudo, coerente com
  banco sem vestígios cadastrados ainda) e nome/perfil do usuário logado
  na navbar
- Contraste de cor calculado manualmente (WCAG) para os pares
  texto/fundo e botão primário, claro e escuro: todos ≥ 6:1, acima do
  mínimo AA (4.5:1)
- Sem ferramenta de browser/screenshot disponível neste ambiente para
  validação visual direta — verificação feita via HTML renderizado e
  cálculo de contraste; recomenda-se abrir no navegador antes de dar a
  tela por definitivamente concluída
