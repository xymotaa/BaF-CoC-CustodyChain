# v0.64.0 — Migração global do frontend

## Fases concluídas

- Fase 4: tabelas adaptativas (`tabela-operacional`) e tabelas densas (`tabela-arquivo`, `tabela-forense`) usam wrappers com rolagem apenas local e preservam identificadores forenses completos.
- Fase 5: as 20 `@section Styles` foram removidas; regras compartilhadas migraram para `wwwroot/css/componentes.css` e as Views passaram a usar contratos canônicos de cabeçalho, botão, formulário e grade.
- Fase 6: login, wallet, verificador público, identidade, auditoria, relatórios, dashboard e processamento pericial usam o mesmo sistema de tokens, cartões, estados e reflow.

## Compatibilidade

Não houve alteração de controller, rota, ViewModel, antiforgery, `id`, `name`, `data-*`, contrato DID/Wallet ou regra de autorização. As exceções mantidas são classes semânticas de domínio, como timeline, recebimento, relatório e evidência forense; sua apresentação está centralizada em `componentes.css`.

## Validação

- Foram adicionados testes de regressão para impedir novos estilos inline e confirmar os contratos canônicos.
- `dotnet build` e a suíte web sem MySQL opt-in foram executados localmente; os testes MySQL não fazem parte desta fatia visual.
- A página pública de login foi aberta no Firefox headless em 320, 375, 768, 1024 e 1440px. A instância ativa do laboratório ainda serve Razor compilado anterior, com CSS inline legado, portanto não valida este conjunto de Views até ser reiniciada com o build atual.
- A validação autenticada, dos temas explícitos e do zoom real continua dependente de uma sessão autorizada no laboratório já atualizada.

## Diagnóstico visual após reinício

- A inconsistência observada no laboratório não era causada pelo cache de `componentes.css`: o processo anterior servia Razor compilado com blocos `<style>` legados das Views, que tinham precedência sobre os contratos globais.
- Após reiniciar a aplicação com o build atual, a resposta de `/entrar` não contém CSS inline e o hash de `componentes.css` servido corresponde ao arquivo versionado.
- As capturas públicas de login e verificador em Firefox headless confirmaram o reflow do formulário em 320px e 1440px. Para validar alterações em Razor, o laboratório deve carregar o build que as contém antes da inspeção visual.
