Escolhido para validar o pipeline EF Core → MySQL → migration antes de

`Descartado`.

## Decisões e por quê

- **Projeto único** (não solução multi-projeto) — mais simples para
  iniciar um TCC, refatora depois se necessário.
- **EF Core fixado em 9.0.x** dentro de um projeto `net10.0` — o Pomelo
  MySQL provider ainda não tem release compatível com EF Core 10 (mais
  recente é `9.0.0`, trava em `EntityFrameworkCore.Relational <= 9.0.999`).
  Ficou pinado nos pacotes `Microsoft.EntityFrameworkCore.*` do
  `CustodyChain.Web.csproj`. `TargetFramework` continua `net10.0`.
- **`AllowMissingPrunePackageData=true`** em `src/Directory.Build.props` —
  o `dotnet-sdk` empacotado pelo Arch/CachyOS (via pacman) não inclui o
  pack `Microsoft.AspNetCore.App.Ref` (só o `Microsoft.NETCore.App.Ref`),
  causando `NETSDK1226` antes mesmo da restauração NuGet normal rodar. É
  o workaround que a própria mensagem de erro do SDK sugere; não afeta o
  build, só desativa uma otimização de poda de referências redundantes.

## Ambiente

- `dotnet-ef` está instalado globalmente (`dotnet tool install -g
  dotnet-ef`) mas `~/.dotnet/tools` não está no `PATH` do fish desta
  máquina — comandos de migration precisam do caminho completo
  (`~/.dotnet/tools/dotnet-ef`) até isso ser ajustado no shell.
